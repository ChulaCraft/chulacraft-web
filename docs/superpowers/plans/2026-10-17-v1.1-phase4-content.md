# v1.1 Phase 4 — Content without a developer

**Spec:** `docs/superpowers/specs/2026-10-16-v1.1-roadmap.md` → Phase 4.
Status: implemented 2026-10-17, not committed.

**Goal:** staff change announcement images, the gallery, the team list and the
site's copy/links from `/admin`, with no code change or redeploy.

## Already covered (no work)

- **Events split from achievements:** `public.events` is its own table with its
  own admin (`/admin/commu/events`) and public pages (`/events`, `/events/[id]`).
  Achievements only point at an event through `achievement_awards.event_id`.
- **Maintenance banner:** a pinned announcement with severity `maintenance`
  already shows site-wide under the header (`announcement-banner.tsx`).

## Decisions

- Images reuse the achievements bucket and `images.ts` (`imageError`,
  `imageKey`, `publicImageUrl`) under new prefixes: `announcements/`,
  `gallery/`, `team/`. No new bucket.
- Every new table follows the existing pattern: RLS on, no direct grants, public
  reads through a security-definer `list_*` RPC, writes through security-definer
  RPCs that re-check the community staff role and write `log_account_change`.
- Site settings are one row per key in `public.site_settings (key, value)`, keys
  fixed by a check constraint. Code keeps today's values as fallbacks, so an
  empty table renders the site exactly as now.
- Reorder = up/down buttons (no drag library; works by keyboard).

## Answers (kaikub, 2026-10-17) and what was built

1. Team page lists **staff and contributors**: name, role, section, bio, photo,
   optional player-page link. `/team`, edited at `/admin/commu/team`.
2. The five built-in `/public` pictures stay **only as the fallback** when the
   gallery is empty (or can't load).
3. Switches picked from a scan of the site: **Registration open** (API route
   refuses add/change; the RPCs are server-only so that is the whole gate) and
   **Player reports open** (DB trigger on `reports`, Report button hidden).
   Maintenance stays a pinned Maintenance announcement.

- One migration `20261025000001_site_content.sql`, test `site_content.test.sql`.
- Discord links all point at `/discord`, which redirects to the invite set in
  `/admin/settings`, so client components follow the setting too.
- Settings are admin-only (System group); gallery/team are community staff.
- Skipped: browser-side image compression (event form has it), drag reorder.

## Revision (kaikub, 2026-10-17, same day)

- **Gallery groups:** staff create a group ("Lobby building day"), then add
  pictures to it. Public `/gallery` shows each group; `/about` shows three
  pictures and links there. Pictures can move between groups.
- **Team generations:** Gen 0, Gen 1, … each with Board (department heads),
  Members, Contributors and Sponsors. `/team` opens on the newest generation
  that has people, with tabs for the others. Sponsors can link a website.
- **Settings** open filled with what the site shows now; a value left at the
  built-in default is stored as "not set".
- **Pages:** Rules, Privacy and Terms are Markdown in `site_pages`, edited at
  `/admin/pages`, defaulting to the text that shipped (converted from JSX).
  Markdown gained tables and `/site` links.
- **Live preview** beside every content form: settings (real homepage hero),
  pages (real page), announcements (item + pinned banner), gallery picture,
  team card. `src/components/form-preview.tsx` reads the form on each input.
- Content reads are live per request (React `cache`), not `unstable_cache`:
  tag invalidation served the stale copy once after each save. Caching is a
  Phase 7 item.
