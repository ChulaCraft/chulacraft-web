# v1.1 Phase 3 (rest) — Profile banner, player showcase, report dialog, motion

**Spec:** `docs/superpowers/specs/2026-10-16-v1.1-roadmap.md` → Phase 3.
Already shipped: Thai font stack, Events page redesign, event categories.

**Goal:** Profile and public player pages share one banner header with stats;
the public page shows event history; reporting moves out of a bottom-of-page
disclosure into a dialog opened from the header; success states animate once.

**No mockup in the repo** for the profile page — built from the roadmap text
("two-column info cards, banner header"). The two-column layout already exists
on `/dashboard`; only the banner is new.

## Decisions

- **Shared primitives:** `globals.css` already has `panel`, `badge`, `chip`,
  `alert`, `skeleton`, `dialog`. No React wrapper per primitive. Only one new
  shared component: `ProfileBanner`, because two pages render it.
- **Rare achievements:** rarity is admin-set in Phase 5 and does not exist yet.
  Showcase uses event history + stats now; rarity tier slots in with Phase 5.
- **Event history** comes from achievement entries (`event_name`), not a new
  RPC: an event shows up once per player, with the badges earned there. Real
  attendance (QR check-in) replaces it in Phase 5.
- **Report dialog:** native `<dialog>` like `ConfirmAction`. Category becomes
  radio cards (one tap on mobile, every option visible). Server action and
  error codes unchanged.
- **Motion:** one `cc-enter` keyframe (opacity + 4px rise, 180 ms) on
  `.alert-success` and newly shown dialogs. The global reduced-motion rule in
  `globals.css` already turns it off.
- Server-dependent stats (online, builds, playtime) stay hidden until the
  Minecraft endpoint exists.

## Addendum — profile banners (2026-10-17, kaikub request)

- Banner header: more room (120 px strip, 104 px avatar, wider padding).
- Banners are four-colour palettes (`public.banners`), no uploads. Four free
  defaults (Dusk, Meadow, Ocean, Ember); five unlockables (Sakura, Aurora,
  Nether, The End, Gold).
- Unlock: an event's "Reward banner" (event form) goes to everyone awarded a
  badge at that event; staff (community area) can give / take back on
  `/admin/users/[id]`. Ownership is computed, so losing it falls back to Dusk.
- Players pick on `/dashboard?edit=banner`; locked ones show how to earn them.
- Migration `20261021000001_profile_banners.sql`, test `profile_banners.test.sql`.
- Staff design banners at `/admin/commu/banners` (name + 4 colour pickers,
  live preview; edit/delete unlock banners; defaults locked). Migration
  `20261022000001_banner_admin.sql`, test `banner_admin.test.sql`.
- Banner pictures (staff only): exactly 1500×300 PNG/JPEG/WebP, ≤ 2 MB, still
  image; checked in the browser and again with sharp on the server; stored in
  the achievements bucket under `banners/`. Header shows them at 5:1; colours
  stay as swatch + fallback. Migration `20261023000001_banner_images.sql`
  (also adds the missing staff select policy on storage, without which every
  cover/picture removal silently did nothing).
- One style per banner (`20261024000001_banner_styles.sql`): Colours, Picture
  (PNG/JPEG/WebP, still) or Animated GIF — files exactly 1500×300, ≤ 2 MB.
  File styles get their four colours from the image (quarter averages); a GIF
  also stores a PNG of its first frame, used under prefers-reduced-motion and
  in swatches.
