# v1.1 Phase 6 — Insights (charts)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** `.omc/specs/deep-interview-v1.1-phase6-insights.md` (deep interview, 18% ambiguity) and
`docs/superpowers/specs/2026-10-16-v1.1-roadmap.md` → Phase 6.
Status: pending approval. **Starts after Phase 5 has shipped** (uses `event_attendance`, `achievements.tier`).

**Goal:** a cloud-console-style `/admin/insights` (range picker, role-scoped tabs, metric tiles with delta +
sparkline, hand-rolled SVG charts, CSV per chart, print-to-PDF) plus a Players tile strip on `/admin/players`.

**Architecture:** one security-definer RPC per tab returns jsonb for the requested range *and the period before
it* (for deltas). Pure TS turns that into zero-filled Bangkok-day series. A small set of SVG chart components
share one frame (title, tooltip, screen-reader table, CSV button). The page is a Server Component that keeps tab
and range in the URL.

**Tech stack:** Next 16 App Router, React 19, Supabase Postgres (pgTAP), Vitest, Playwright. No new runtime
dependency.

## Global Constraints

- Charts are hand-rolled SVG. No chart library. Load the `dataviz` skill before writing chart code.
- Data pattern: RLS on, `revoke all` from anon/authenticated, `security definer` + `set search_path = ''`,
  explicit grants. New authenticated grants go into the allowlist in
  `supabase/tests/default_function_privileges.test.sql`.
- Day buckets are **Asia/Bangkok** days, the same as `snapshot_stats_daily` (`20261017000002_stats_daily.sql:24`).
- Range values `7d | 30d | 90d | all` → `p_days` 7 / 30 / 90 / null. Default `30d`.
- Tab access, mirroring `staff_can` (`20261019000001_staff_roles.sql:23`):
  Overview / Players / Staff activity → `staff_can('admin')`; Events → `staff_can('community')`;
  Community → `staff_can('moderation')`. Result: owner/admin see all, `event_staff` sees Events only, `moderator`
  sees Community only.
- Funnel failures store **no user identifier**. The funnel itself comes from existing timestamps. No Vercel `track()`.
- UI baseline for every UI task: Thai font stack, loading/empty/error states, 375 px without horizontal scroll,
  keyboard reachable, no chart draw-in animation (`prefers-reduced-motion` or not: charts render static).
- Before using any Next API, read its page under `node_modules/next/dist/docs/`.
- No commit without kaikub's approval. Run `graphify update .` after code changes.

## Review Focus

1. **Bangkok midnight:** a signup at `2026-10-21T17:30Z` is Bangkok 22 Oct 00:30 and counts on 22 Oct, not 21 Oct.
   Tested in Task 1 (SQL) and Task 2 (`fillDays`).
2. **Missing snapshot day** (cron skipped): the snapshot line shows a **gap**, not a drop to 0 and not a joined
   line. Count series (signups/day) zero-fill instead. Tested in Task 2 and Task 3.
3. **CSV with hostile or Thai text:** an event named `=HYPERLINK(...)` or `+cmd` exports as text (prefixed `'`).
   Thai names open correctly in Excel (UTF-8 BOM). Tested in Task 2.
4. **Tiny series:** 0 or 1 points, all-zero values, or a previous period of 0. The sparkline renders without
   NaN/Infinity in path data, and the delta reads "New" instead of "∞%". Tested in Task 2 and Task 3.
5. **Bad URL params:** `?range=999d&tab=nope`, or a tab the role may not see, falls back to the first allowed tab
   and `30d` with no error and no FORBIDDEN banner. Tested in Task 5.

## Decisions

- **One RPC per tab** (`insights_players`, `insights_funnel`, `insights_events`, `insights_community`,
  `insights_staff`), each `(p_days int)` → `jsonb`. Each returns series covering `2 × p_days` days ending today
  (Bangkok), so the delta needs no second call. For `p_days null` ("all") it returns everything and no delta is
  shown. Overview has no RPC of its own: it reuses the players, funnel, events and community payloads. All five
  RPCs run in one `Promise.all`.
- **Funnel = cohort funnel.** The cohort is non-staff users created in the range. A step counts as reached if the
  user is in that state *now*. Steps: `signed_in` (in cohort) → `discord` (has `auth.identities` provider
  `discord`) → `verified` (`is_chula_verified` or `guest_verified_at is not null`) → `registered` (has a
  `minecraft_registrations` row) → `whitelisted` (`whitelisted_at is not null`). No new timestamps are needed.
- **Failure counting** goes into `funnel_failures (day date, step text, code text, count int, pk (day, step, code))`.
  Writes go through `record_funnel_failure(p_step, p_code)`, which is **service_role only**, so a player can't
  inflate counts. Steps: `minecraft` (registration route), `verify` (`/verify?error=` codes from
  `src/lib/reconcile-identities.ts`). Code check: `^[A-Z0-9_]{2,40}$`. A new `src/lib/supabase/service.ts`
  `serviceClient()` uses `getSecretSupabaseEnvironment()` (`src/lib/env.ts:17`). Recording is fire-and-forget:
  a failure to record never changes the player's response.
- **Snapshot series are not zero-filled** (a missing day is a gap). **Count series are zero-filled.**
- **CSV is built on the client** from the exact data the chart received (no extra route). It includes a BOM and
  escapes formula-leading cells.
- **Print:** `@media print` in `insights.module.css` hides the admin nav, range picker and buttons. It forces light
  tokens, sets `break-inside: avoid` on panels, and shows a header line "ChulaCraft Insights · <tab> · <range> ·
  printed <date>".
- **Nav:** new link "Insights" in the People group (area `players_read`, so every staff role sees it). The page
  shows only the allowed tabs. A role with none gets `notFound()`.
