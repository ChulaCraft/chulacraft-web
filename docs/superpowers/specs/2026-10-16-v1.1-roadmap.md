# ChulaCraft Web v1.1 — Roadmap Spec

Date: 2026-10-16 · Owner: kaikub · Status: approved scope, Phase 1 planned

v1.1 is too big for one plan. It is split into phases; each phase gets its own
implementation plan in `docs/superpowers/plans/` and ships on its own.

## Decisions already made

- Community admin lives under `/admin/commu`:
  `/admin/achievements` → `/admin/commu/achievements`,
  `/admin/achievements/events` → `/admin/commu/events`,
  `/admin/announcements` → `/admin/commu/announcements`. Old URLs redirect.
- Achievement rarity is **set by admin** (a tier on the achievement), not computed.
- Discord role sync is **one-way, website → Discord**. Removing a role in Discord does nothing on the site.
- Admin roles: **owner / admin / moderator / event-staff**.
- "Secondary font" = the body font, Atkinson Hyperlegible (`--font-body`). Display font is Pixelify Sans.
- Charts: start with hand-rolled SVG (no new dependency). Add a library only if tooltips/zoom are needed everywhere.

## Global constraints (every phase)

| Area | Requirement |
|---|---|
| Performance | Optimize large hero images, lazy-load below-the-fold media, minimize unnecessary JavaScript. |
| Responsive | Test navigation, forms, cards, typography on narrow screens. |
| Accessibility | Text contrast, keyboard navigation, focus indicators, form labels. |
| Security | Supabase RLS, server-side authorization, OAuth/session handling, secret management. Every new table follows the existing pattern: RLS on, no direct grants, security-definer RPCs that re-check role. |
| Reliability | Loading, empty, error, success states on every data-dependent feature. |
| SEO / sharing | Page titles, descriptions, social preview images, favicon. |
| Measurement | Track registration starts, successful submissions, failures — no unnecessary personal data. |
| Motion | No decorative animation. Every animation tells the story or communicates state. Site stays fully usable with `prefers-reduced-motion: reduce`. |
| Thai text | Thai copy uses a Thai-capable font (IBM Plex Sans Thai / Noto Sans Thai); Pixelify Sans has no Thai glyphs. |

## Phases

### Phase 1 — Quick fixes & admin navigation  → `plans/2026-10-16-v1.1-phase1-quick-fixes.md`
1. Homepage hero: "Build. Explore. Connect." → "BUILD EXPLORE at ChulaCraft!"
2. Header shows the Discord name even after a Google sign-in.
3. Admin dashboard stat numbers in the body font.
4. Move community admin routes to `/admin/commu/*` with redirects; Events gets its own list page.
5. Grouped admin nav (People · Community · Moderation · System) with active state.

### Phase 2 — Admin power tools
- Players: full table with infinite scroll, sortable columns, URL filters (`?filter=chula_verified|guest|unverified|removed`).
- Dashboard stat boxes link to those filters ("81 Verified Chula" → list of those 81).
- Unverified players + Guest list cards become real (they are saved filters).
- Bulk actions on selected rows: award achievement, verify, ban, change role.
- CSV export of the current filtered list.
- Admin command search (Ctrl+K): players, events, achievements, settings.
- Admin user page shows/edits everything the user sees in `/settings` (customer support).
- Role levels: add `moderator` (reports/appeals only) and `event-staff` (events/achievements/check-in only); RPC role checks updated.

### Phase 3 — Design system & UI redesign
Skills: `frontend-design`, `motion-design`.
- Shared primitives: card, chip/category tag, date badge, stat tile, section header, empty/error/loading states, skeletons.
- Thai font added to the font stack.
- Events page per mockup: featured 16:9 hero card + upcoming grid, category chip, "View event" CTA, no duplicated poster text.
- Profile page per mockup: two-column info cards, banner header. Server-dependent stats (online, builds) hidden until the server endpoint exists.
- Public player page showcase: rare achievements, event history.
- Report-player UI redesign.
- Motion: meaningful state transitions only (award unlocked, form success, list insert), all disabled under reduced motion.
- Mobile pass on every page.

### Phase 4 — Content without a developer
- Announcement images (reuse `src/app/admin/achievements/images.ts` upload path).
- Gallery: admin upload, reorder, delete.
- Team page: admin add/edit/delete members.
- Site settings: homepage copy, server address, links, rules, feature toggles, **maintenance mode** banner.
- Events split fully from achievements in data/UI (announcement vs event are separate things).

### Phase 5 — Achievements & engagement
- Rarity tier (admin-set) shown on cards and showcase.
- Achievement → Discord role assignment (website → Discord only, via a bot queue like `announcements_discord_queue`).
- **Event QR check-in** → auto-award the event achievement.
- Discord reminders before events + "Add to calendar" (.ics).
- In-site notifications (bell): achievement earned, appeal answered, report resolved.

### Phase 6 — Insights (charts)
Skill: `dataviz`.
- Daily snapshot table (`stats_daily`) via scheduled job — **ship this as early as possible**, history only starts when it is on. (Candidate to pull into Phase 2.)
- Players section charts: signups/day, total over time, funnel (signed in → verified → whitelisted), faculty/major split, Chula vs guest.
- `/admin/insights`: all of the above + events & interest, achievement ownership, reports/appeals trend, admin activity, registration funnel measurement, link to Vercel Analytics.

### Phase 7 — Performance, reliability, hardening
Skills: `vercel:performance-optimizer`, `security-review`.
- Measure first: Vercel function region vs Supabase region, waterfall of auth + role + data calls per admin page.
- Collapse sequential calls (`Promise.all`), cache public pages, prefetch admin links, skeletons.
- Error monitoring + alerts.
- SEO metadata, OG images, favicon audit.
- Accessibility and contrast audit.

## Deferred (needs Minecraft server endpoint)
Leaderboards, playtime, online status, builds count.
